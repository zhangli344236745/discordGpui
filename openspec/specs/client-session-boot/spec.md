# client-session-boot Specification

## Purpose

定义登录后的首屏同步：把后端用户、服务器、频道、成员、角色、好友、私信与未读状态水合到现有 GPUI 界面，并保证切换账号或退出时彻底清理。

## Requirements

### Requirement: 首屏同步的完整性

登录成功后客户端 SHALL 依次加载当前用户、服务器列表、每个服务器的频道树/成员/角色/权限、好友、私信、频道视图状态与未读计数，并在完成前显示加载态。任一必需请求失败 MUST 中止进入主界面并允许重试。

#### Scenario: 同步完成

- **WHEN** 所有首屏请求成功
- **THEN** 服务器栏、频道侧栏、成员栏、私信列表、好友页与未读角标都显示后端数据，而不是种子数据

#### Scenario: 同步失败

- **WHEN** `/servers` 或频道树请求失败
- **THEN** 保持加载/错误界面，提供「重试」，不展示半套种子数据

#### Scenario: 重试成功

- **WHEN** 用户在错误界面点击重试且后端恢复
- **THEN** 重新执行同步并进入主界面

### Requirement: 身份与映射稳定

客户端 SHALL 为服务器、分类、频道、成员、角色、消息、好友、私信保存后端字符串 id。界面可继续用显示名做键，但所有写操作 MUST 使用保存的后端 id；不得用显示名反查资源。

#### Scenario: 同名频道

- **WHEN** 两个频道显示名相同但 id 不同
- **THEN** 发消息、置顶、删除等操作命中正确的频道 id

#### Scenario: 改名

- **WHEN** 服务器或频道在另一端改名并收到事件
- **THEN** 客户端更新显示名但保留原 id，后续操作仍指向同一资源

### Requirement: 未读与在线状态水合

客户端 SHALL 使用 `/notifications/unread-counts` 与 `PRESENCE_UPDATE`/成员状态初始化未读角标与在线圆点。标记已读 MUST 以服务端返回为准更新本地计数。

#### Scenario: 首屏角标

- **WHEN** 同步完成且某频道有 3 条未读
- **THEN** 侧栏该频道显示 3，服务器汇总角标同步显示

#### Scenario: 进入频道

- **WHEN** 用户打开频道并触发已读
- **THEN** 该频道角标清零，服务器汇总相应减少

### Requirement: 退出与切换账号的清理

退出登录或切换到另一账号时，客户端 MUST 关闭 WebSocket、清空所有实体状态、未读、草稿缓存与选中会话，再回到登录界面；不得让上一账号的数据出现在新会话中。

#### Scenario: 退出后重新登录

- **WHEN** 用户退出后以另一账号登录
- **THEN** 只看到新账号的服务器、私信与通知，旧账号缓存不可见

#### Scenario: 切换期间事件

- **WHEN** 退出过程中旧 WebSocket 仍收到事件
- **THEN** 事件被丢弃，不写入新会话

### Requirement: 离线演示模式的边界

离线演示模式 MUST 与在线模式互斥：只读本地种子/快照，所有写操作仅改本地状态并明确标注「未连接后端」，不得尝试发送到服务器。

#### Scenario: 离线发消息

- **WHEN** 离线演示模式下发送消息
- **THEN** 消息只出现在本地并显示离线标识，不产生网络请求

#### Scenario: 回到在线

- **WHEN** 用户退出离线模式并登录
- **THEN** 本地演示数据被后端数据替换，不合并
