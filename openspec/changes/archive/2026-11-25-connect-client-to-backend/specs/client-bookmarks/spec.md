# Spec Delta

## Purpose

定义书签的稳定身份与端到端行为：以消息 id 保存频道/私信书签，支持跨会话跳转、原消息删除后的墓碑展示与多端同步，替代按正文反查。

## ADDED Requirements

### Requirement: 书签使用稳定消息身份

书签 MUST 保存 `target_kind`（channel/dm）与 `target_id`（消息 id），不得以正文、作者或时间反查原消息。保存与取消 MUST 幂等，并以 `BOOKMARK_UPDATE` 同步多端。

#### Scenario: 保存频道消息

- **WHEN** 用户在消息菜单点击「保存消息」
- **THEN** 书签列表出现该条，刷新或重启后仍可跳转

#### Scenario: 保存私信消息

- **WHEN** 用户保存一条私信消息
- **THEN** 书签列表标记为私信来源，跳转回到对应 DM

#### Scenario: 重复保存

- **WHEN** 用户对已保存消息再次点击保存
- **THEN** 不产生重复书签，状态保持已保存

### Requirement: 书签跳转与定位

点击书签 MUST 切换到目标会话并定位到消息 id；消息不在当前缓存时 MUST 通过 `before/after` 游标拉取直到找到或确认不存在。定位后 MUST 短暂高亮。

#### Scenario: 跨频道跳转

- **WHEN** 用户点击另一个服务器的书签
- **THEN** 客户端切换到该服务器/频道，加载历史并高亮目标消息

#### Scenario: 目标不在缓存

- **WHEN** 目标消息早于当前已加载窗口
- **THEN** 客户端继续向前分页，找到后定位，不显示空白

#### Scenario: 无法定位

- **WHEN** 服务端确认消息不存在或已删除
- **THEN** 显示「原消息已删除」，不发生无限拉取

### Requirement: 删除后的墓碑与清理

原消息被删除后，书签 MUST 仍保留并显示墓碑（来源、作者、删除状态），不得崩溃或静默消失；用户仍可手动移除书签。

#### Scenario: 原消息删除

- **WHEN** 书签指向的消息被软删
- **THEN** 列表显示「原消息已删除」，跳转按钮禁用或提示不可定位

#### Scenario: 移除书签

- **WHEN** 用户点击书签的移除
- **THEN** 书签从列表与后端删除，事件同步到其他端

### Requirement: 书签搜索与多端同步

书签面板 SHALL 支持按关键词过滤当前用户书签；收到 `BOOKMARK_UPDATE` 时 MUST 只更新对应消息的书签状态，不整表重建。

#### Scenario: 搜索书签

- **WHEN** 用户输入关键词
- **THEN** 列表只显示正文命中的书签，清空后恢复全部

#### Scenario: 另一端保存

- **WHEN** 同一账号在另一设备保存消息
- **THEN** 本端书签列表出现该条，无需手动刷新

#### Scenario: 另一端移除

- **WHEN** 同一账号在另一设备移除书签
- **THEN** 本端对应项消失，其余书签不受影响
